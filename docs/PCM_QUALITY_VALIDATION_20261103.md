# OBS受信側のオフライン音質測定

2026-11-03。受信の連続性とは別に、線形補間の高域減衰を確認した。音質の一般配布受入は未完了。
実機の1時間運転は [本体の記録](../../VSTHost-input-clock/docs/INPUT_CLOCK_CORRECTION_VALIDATION_20261103.md)を参照する。

## 方法と確認範囲

DLLと同じ `src/pcm.hpp` のReaderを、`pcm_tests --quality` からheap上のwireデータへ適用した。
共有メモリIPC、実OBSアプリ、実デバイス、実時間のCPU負荷を測る試験ではない。
48kHz stereo f32の同じ70秒を使い、100/1000/10000/19000Hz各peak 0.05の合成音を0/±37/±500ppmで処理した。
入力と出力raw、統計、時系列、SHA-256、波形/PSD、音量を揃えた試聴WAVを保持する。
各音の±80Hzの帯域内powerを比較し、clock補正による周波数変動も含める。固定周波数からのズレをそのまま歪率やSNRと呼ばない。

## 結果

| 入力の速度差 | 100Hz | 1kHz | 10kHz | 19kHz |
| --- | ---: | ---: | ---: | ---: |
| 0ppm | 0.000dB | 0.000dB | 0.000dB | 0.000dB |
| +37ppm | -0.000dB | -0.012dB | -1.228dB | -3.936dB |
| -37ppm | -0.000dB | -0.012dB | -1.223dB | -3.912dB |
| +500ppm | -0.000dB | -0.012dB | -1.233dB | -3.959dB |
| -500ppm | -0.000dB | -0.012dB | -1.233dB | -3.959dB |

全てのモデルで開始後のunderrun/overrun/invalid/staleは0。起動のprefillと入力先頭のskipは別のcounterで記録した。
0ppmの位相が固定した条件では劣化が見えず、速度差がある条件で高域が減衰した。連続性の合格や音量合わせだけでは、この帯域差を検出できない。
以前のUSBマイク→OTT参照録音の同じ70秒も+37ppmで処理し、RMSは-0.188dB。これは生マイクや全チェーンの音質比較ではなく、受信補間器だけの比較。
聴感は未判定。44.1/96kHz間の音質・帯域外入力のalias除去も、この測定では確認していない。

## 測定用コードの確認

C++のビルドとCTest 2件、Python 15件が成功。既知の半分の振幅を4帯域とも-6.0206dB、音量合わせ倍率2として測る回帰試験を含む。
実Readerの最小4秒入力→解析が成功し、3秒入力・既存出力先の拒否も確認した。
runtimeのC++3ファイルとDLLは変更していない。測定機能は明示したCLIだけで動き、マイク・OBS・物理出力を起動しない。

## 次の改善と公開の条件

受信側は帯域を制限したSinc系の補間へ置き換える案を優先する。
係数と作業領域をcallbackの前に確保し、描画側の無割当・非ブロッキングと、独立した出力clockを維持する。
同じraw入力の音量を揃えた試聴と帯域特性、対応rate間のalias除去、負荷・ミュート・再接続を比較する。DLLが変わる場合は新しいDLLで実時間の1時間検証を行う。
現在のローカル候補を、音質受入済みの一般配布物として案内しない。導入・署名・対応ソースの残件は [配布準備](DISTRIBUTION_READINESS.md) に残す。

原データ: ignored `build/pcm-quality-20261103/`。合成音の同一入力は `probe.f32`、各 `tone-*-analysis/analysis.json` と `comparison.png`、録音素材は `voice-37/` と `voice-37-analysis/`。
私的な録音はローカル測定領域だけに保持し、ソースZIPへ含めない。
